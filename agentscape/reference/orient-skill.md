# The orient-skill workflow — ship a city its own orient skill

A workflow the installer runs during a cityscape session when the city is (or
is becoming) a **companion being** — a city that knows and remembers the user,
not just orchestrates work. The deliverable is the city's **own orient skill**:
the closer that assembles the whole being's state and closes the loop.

The orient skill is a **feature gas-cityscape ships**. It is a real `SKILL.md`
the user's city gets — not a mayor reference. The installer adapts the shipped
seed (`assets/orient-skill.template.md`) to the city, so the skill names the
city's actual seats, its actual pipeline, its actual stocks. That is what makes
it the closer: it works because it knows *this* city and *this* user.

## When to run this

- During a **Craft** or **Rework** session where the city adopts the
  companion-nervous-system pattern (`reference/companion-nervous-system.md`).
- When the user wants the city to be able to "orient" — assemble its whole
  state, reconcile its parts, and surface the one frontier.

Run it after the city's seats and pipeline exist (or are planned), so the
orient skill has something real to name.

## The five moves

### 1. Sense — check what's there to orient

Read what the city actually has, before planning anything:

- **The force** — does `twin/self/origin.md` + `twin/self/principles.md` exist?
- **The seats** — which facets exist (mind, body, eyes, heart)? Each with a
  handoff cache?
- **The pipeline** — are the propagation orders wired (capture → distill →
  place → link → verify → prune)?
- **The stocks** — does `twin/self/stocks.md` exist?
- **The reconciliation** — do seats read each other's handoffs?

This doubles as a **readiness check**. For a new city, it tells you what's
missing before the orient can be written. For an existing city, it tells you
what the orient will assemble.

**Completion criterion:** you can name, from evidence, which of the five parts
exist and which are missing — and you have the actual paths the orient will
read.

### 2. Plan — design the orient for THIS city

Design the orient skill's shape from what sense found:

- **What does this city's orient assemble?** Its actual seats, its actual
  pipeline, its actual stocks — the paths from step 1.
- **What is the live thread?** The thing the user is carrying right now that
  orient should surface.
- **What is the one frontier?** The single decision that matters, offered as a
  choice — not a backlog.

The orient skill is not a template with blanks. It is written for this city,
naming its real parts.

**Completion criterion:** you can state, in one paragraph, what this city's
orient will assemble and what it will surface.

### 3. Grill — work with the user

Invoke `/grill-me` (it runs a `/grilling` session) — one question at a time,
recompute the frontier after each answer. Record each answer as a decision on
the wayfinder. Do not guess a preference you did not elicit.

Grill on what matters for *this* orient:

- What should orient surface when the user asks?
- What is the live thread the user is carrying?
- What does the user want orient to close?

**Completion criterion:** every question the user cares about is answered and
recorded on the wayfinder, or is a named decision ticket in Not yet specified.

### 4. Write — write the city's own orient skill

Copy the shipped seed `assets/orient-skill.template.md` into the city's skills
as `orient/SKILL.md`, then adapt it to the city. It encodes, in the city's own
words:

- **Assemble the state** — the actual paths from step 1, in order.
- **Reconcile the parts** — when seats saw contradictory user states, hold
  both, in the right order; do not pick a winner.
- **Name the bleeding stock** — which stock is bleeding, and the one flow to
  move.
- **Surface the one frontier** — the single decision that matters, as a choice.
- **Speak like a person** — not a status dump. A person who knows the user,
  talking to them. The reading is invisible; the knowing shapes the words.

**Completion criterion:** the orient skill exists in the city, names the city's
actual seats, pipeline, and stocks, and the user approved it.

### 5. Review — against writing-for-agents

Review the written skill against `writing-for-agents` before it lands:

- **Leading words** — does it use compact concepts the agent thinks with
  (e.g. *frontier*, *bleeding stock*), not sentences?
- **Completion criteria** — can the agent tell done from not-done? Are the
  bounds checkable and exhaustive?
- **Progressive disclosure** — is reference pushed behind pointers, or does the
  top bloat?
- **No-ops** — does every sentence change behavior vs the default? Delete
  sentences that say nothing.
- **Pruning** — is every line relevant? Does it name this city, or is it a
  generic template that could be any city?

**Completion criterion:** the orient skill passes the writing-for-agents review
— every line earns its place, and it names this city, not any city.

## Done when

- The orient skill exists in the city and names the city's actual seats,
  pipeline, and stocks.
- The user approved it (grilled, not guessed).
- It was reviewed against writing-for-agents and every line earns its place.
